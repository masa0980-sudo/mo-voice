# exe ビルドについて

PyInstaller で `MOVoice.exe`（単一フォルダ形式）を作るための一式です。

> **現時点では exe を配布していません。** ビルドは通りますが、下記の理由で
> 実行できない環境が多いと判断したためです。本体リポジトリの README も
> ソースからの導入だけを案内しています。
> ここに残してあるのは、**コード署名を導入したときにすぐ配布へ移れるように**
> するためです。

## ビルド方法

```bash
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt pyinstaller
packaging\build.bat
```

出力は `dist\MOVoice\MOVoice.exe` です。フォルダごと配布します
（`MOVoice.exe` だけを取り出しても動きません）。

コンソール付きで動かして例外を見たい場合は、`MOVoice.spec` の
`console=False` を `True` に変えてビルドしてください。ウィンドウアプリとして
ビルドすると標準出力が繋がらず、起動直後の例外が一切見えなくなります。

## 配布を見送っている理由（2026-08-28 実測）

**ウイルスバスター クラウド（Trend Micro）が、PyInstaller 製の署名なし exe を
実行段階でブロックします。**「不審なファイルのブロック／このファイルは安全でない
可能性があります」というダイアログが出て、`Access is denied` で起動できません。

原因の切り分けに使った手順と結果:

| 検証 | 結果 |
|---|---|
| MO Voice の exe（222MB・依存多数） | ブロック |
| **`print` 一行だけの最小 exe** | **ブロック** |
| スキャンの除外フォルダに登録して実行 | ブロック |
| Trend Micro を再起動（除外登録より後）してから実行 | ブロック |
| 別名コピー（新規ファイル扱い）で実行 | ブロック |

`print` 一行の exe でも同じように止まるため、**このアプリのコードや依存関係とは
無関係**です。PyInstaller のローダー構造と、署名がなく実績のない実行ファイルで
あることが理由と考えられます。

**スキャンの除外設定は効きません。** レジストリ上、例外リストは
`HKLM\SOFTWARE\TrendMicro\UniClient\1700\Scan\Exceptions` の一か所しかなく、
そこへ登録して製品を再起動しても、この「不審なファイルのブロック」機能には
適用されませんでした。

日本ではウイルスバスターの利用者が多く、受け取った人の環境でも同じことが
起きます。しかも表示が「不審なファイル」なので、**まず実行してもらえません**。
署名なしで配ると製品の第一印象を損なうと判断し、配布を見送っています。

### 配布を再開する条件

コード署名証明書の導入です。OV 証明書なら提供元が明示され評価が蓄積していきます。
EV 証明書なら即座に信頼されます。ダウンロード数が見込める段階になったら検討します。

誤検知報告という手もありますが、これは署名（パターン）による検出ではなく
**評価ベースの判定**なので、ビルドし直すたびに再発する可能性が高く、
根本的な解決にはなりません。

## ファイル

| ファイル | 用途 |
|---|---|
| `MOVoice.spec` | PyInstaller のビルド定義 |
| `build.bat` | ビルド実行用（**ASCII のみで書くこと**。cmd.exe は `.bat` を システムのコードページで読むため、非ASCIIのコメントが化けて実行される） |
| `../assets/movoice.ico` | exe とタスクバーのアイコン（16〜256px の8サイズ入り） |

`assets/movoice.ico` は `ui/tray.py` の描画コードから生成しています。
アイコンのデザインを変えたら作り直してください。
